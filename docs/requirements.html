1. プロジェクト概要と目的

1.1 背景と目的

グロースレンタカー は、一般レンタカーに加え、キッチンカー・キャンピングカー・ダンプ等の特殊車両、 さらに家電・工具といった物品単体レンタルまでを、単一のプラットフォームで扱う 統合予約サイト兼管理システムです。

車両と物品では貸出単位・必要情報（免許の要否、在庫数の考え方）・表示すべきスペックが大きく異なります。 本システムはこれらの差異を吸収し、一般利用者にはカテゴリごとに最適化された検索・予約体験を、 運営者には全カテゴリ・全拠点を横断した一元管理を提供します。

1.2 最重要要件 — カテゴリ拡張のノーコード化

本プロジェクトの最重要要件 新しい取り扱いカテゴリ（例：新ジャンルの車両や物品）の追加を、 エンジニアの実装作業を一切必要とせず、管理画面の操作のみで完結できること。 料金プラン・スペック項目・オプションを含め、運営者自身が自由に定義・変更できることを設計の中核に据えています。

この要件は、EAV（Entity–Attribute–Value）／JSONカラム方式のカスタム項目定義によって実現しています。 カテゴリごとに「どんなスペック項目を持つか」を管理画面から定義でき、その定義が 車両・物品の登録フォーム、予約サイトのスペック表示、検索の絞り込み条件へ自動的に反映されます。 （詳細は「4. システム全体構成」および「5. 機能要件」を参照）

1.3 参考サービス

一般レンタカーの予約体験・車両詳細の表現については rentacar-samurai を、 多カテゴリ・柔軟なマスタ運用については同種サービスを参考とし、 これらを一つのシステムへ統合・発展させる位置づけです。

2. 運営体制・拠点情報

2.1 運営前提

  • 4拠点での営業。各拠点に常駐スタッフは置かない非常駐運営を前提とする。
  • 全体の対応スタッフは2〜3名。少人数での運営を成立させるため、 全拠点の状況を一画面で一元管理できること、およびスマートフォン対応が必須。
  • 非常駐運営を補うため、予約受付・返却・入金状況の変化はメール自動通知／通知ログで把握できる設計とする。
設計上の含意 「少人数・非常駐」という運営制約が、ダッシュボードの一元表示、スマホ最適化された管理画面、 自動通知（SkyRentStore.notify()）といった機能の設計根拠となっています。

4. システム全体構成

4.1 構成概要

本システムは予約サイト（一般利用者向け）と管理画面（スタッフ向け）の2系統からなり、 両者は共通のデータ層・料金エンジンを介して同一のマスタを参照します。

レイヤー構成要素役割
プレゼンテーション予約サイト（検索・詳細・予約フロー・マイページ）／管理画面（約40画面）利用者・スタッフの操作UI。レスポンシブ対応。
ロジックSkyRentPricing（料金エンジン）／SkyRentAPI料金計算・空き判定・予約生成などの業務ロジック。
データアクセスSkyRentStore全データの読み書きを一元化する抽象化レイヤー。
データストアブラウザ内 localStorage（デモ）／将来はGAS・AWS等のバックエンド永続化。API境界を保ったまま差し替え可能。

4.2 実装形態

  • 静的サイト構成：素の HTML / CSS / JavaScript で実装し、ビルド工程を持たない。 GitHub Pages によるホスティングで動作する。
  • データ層の抽象化：全データアクセスを SkyRentStore / SkyRentAPI に集約。 デモではブラウザ内 localStorage を使用するが、同一のAPIシグネチャを保ったまま GAS・AWS 等の本番バックエンドへ差し替え可能な設計とする。
  • 差し替え容易性：画面側は localStorage を直接操作せず、必ず抽象化レイヤー経由で読み書きする規約とし、 バックエンド移行時の影響範囲をデータ層に限定する。

4.3 カテゴリ拡張エンジン（EAV / カスタム項目）

最重要要件である「ノーコードでのカテゴリ拡張」は、カテゴリ定義に持たせた カスタム項目定義（customFieldDefs）によって実現します。 1つのカスタム項目は「キー・表示名・型（テキスト／数値／選択）・単位・選択肢・検索対象フラグ」で構成されます。

この定義を編集すると…自動的に連動する箇所
カテゴリのカスタム項目を追加／変更車両・物品マスタ登録フォームの入力欄が自動生成される
各車両・物品にカスタム値を入力予約サイトのスペック表示に自動反映される
項目に「検索対象」フラグを立てる予約サイトの絞り込みフィルタに自動で追加される

これにより、新カテゴリの追加・スペック項目の増減・絞り込み条件の変更がすべて管理画面 （categories.html のカスタム項目エディタ）で完結し、エンジニアの介在を不要とします。

8. 決済方法

8.1 現地決済（基本）

初期リリースの標準決済手段は現地決済です。予約時にオンライン課金は行わず、 貸出時に拠点で精算します。○ 実装済

8.2 請求書払い（法人・行政のみ）

法人・行政の利用者に限り、請求書払いを提供します。 不特定の会員に選択肢を見せないよう、許可制で運用します。

要件仕様・実装状況
許可制管理画面で請求書払い許可フラグ（invoiceAllowed）を付与した会員に限り選択可能。○
選択肢の非表示制御フラグが無い会員の予約フローには請求書払いの選択肢を表示しない。○
請求書発行・印刷会社名・住所・案件名・金額・振込先を記載した請求書を発行・印刷。○
発行履歴・入金状況発行履歴と入金状況（未払い／支払済）を管理。○
月次一括請求複数予約をまとめた月次一括請求に対応。○

許可フラグの付与は members.html、請求書の発行・入金管理・印刷は invoices.html、 振込先は settings.billing で管理します。

8.3 オンライン事前決済（将来対応）

Stripe 等によるオンライン事前決済は初期リリース対象外です。拡張 ただし予約の payment.method を拡張可能な形で保持しており、 決済手段の追加を見越した受け口を設計に組み込んでいます（「11. 将来拡張」参照）。

分類要件実装状況
レスポンシブ スマートフォンを最優先とし、PC・タブレット・スマホで利用可能なこと。管理画面もスマホで操作可能なこと。 ○ 実装済 予約サイトはスマホファースト。管理画面はハンバーガーメニューでモバイル対応、表は横スクロール。
多言語 日本語・英語対応。将来的に中国語・韓国語へ拡張可能なこと。 ○ 実装済 SkyRentI18n による日英切替。辞書追加のみで言語拡張が可能な構造。
拡張性 カテゴリ・オプション・料金体系をノーコードで拡張できること。料金計算モジュールが将来の週割・月割にも対応できること。 ○ 実装済 EAVによるカテゴリ拡張、SkyRentPricing による時間/日/週/月の自動選択＋ハイシーズン加算。会員ランク別・将来割引を見据えた拡張設計。
運用性 少人数・非常駐運営を成立させる自動通知と一元管理。 ○ 実装済 予約・返却・入金の変化を notify() でログ化。ダッシュボードで全拠点を一元把握。
保守性・移植性 バックエンド差し替えの影響を局所化できること。 ○ 実装済 データアクセスを SkyRentStore / SkyRentAPI に集約。localStorage の直接操作を禁止する規約で移植性を担保。
セキュリティ 入力値由来のクロスサイトスクリプティング（XSS）等を防止すること。 ○ 実装済 ユーザー入力・データ由来文字列は esc() でHTMLエスケープする規約を全画面で徹底。拡張 認証・通信の本格的なセキュリティは本番バックエンド移行時に実装。
データ保全 運用データのバックアップ・復元手段を備えること。 ○ 実装済 profile.html からデータのバックアップ／復元が可能。
セキュリティに関する注記 デモ版はブラウザ内 localStorage を用いるため、パスワードは平文で保持し、認証は簡易実装です。 本番運用では、後述のバックエンド移行に合わせてパスワードハッシュ化・サーバー側認証・HTTPS通信・アクセス権限制御を実装する前提です。

11. 将来拡張

以下は初期リリース対象外としつつ、設計上の受け口（拡張ポイント）を用意している項目です。 いずれも既存のデータモデル・API境界を保ったまま追加できるよう設計しています。

拡張項目内容設計上の受け口（拡張ポイント）
オンライン決済（Stripe等） 予約時のオンライン事前決済。 予約の payment.method を拡張可能な列挙として保持。決済手段の追加・決済ステータス管理を後付けできる構造。
メール実送信 確認メール・通知メールの実送信。 現状は notify() が送信内容をログ化。同メソッドの実装を実送信API（SMTP／メール配信サービス）へ差し替えるだけで有効化。
本番バックエンド移行 localStorage から GAS・AWS 等の本番バックエンドへ移行。 データアクセスを SkyRentStore / SkyRentAPI に集約済み。API境界を保ったままバックエンド実装を差し替え可能。
多言語（中国語・韓国語） 日英に加え中韓へ拡張。 SkyRentI18n の辞書に言語を追加するのみで対応。UIは既に言語切替に対応済み。
料金体系の拡張 会員ランク別料金、週・月の長期割引の高度化。 SkyRentPricing がプラン選択・割引・ハイシーズン加算をモジュール化。割引ルールの追加を局所変更で実現。
認証・セキュリティ強化 パスワードハッシュ化・サーバー側認証・権限制御。 会員・従業員・権限のデータモデルを保持済み。バックエンド移行と同時に本格的な認証基盤を実装。
拡張方針 本システムは「まず動く形で全機能を提供し、本番運用に向けてデータ層・決済・通知・認証を段階的に強化する」ことを前提に設計しています。 いずれの拡張も画面・業務ロジックの再実装を最小化できるよう、責務を分離しています。
